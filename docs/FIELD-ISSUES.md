## FI-01 🔴 「执行 = 行驶」在实现上不成立：行驶是完成后的过场动画

**现象（实测）**：录第一步执行时发现车完全不动；工作完成后车才开始移动。

**代码定位**：
- `index.html` `driveTo()`：`journey.length <= 1` 分支一帧瞬移（约 :3317），第一步永远没有行驶过程；
- 行驶时长 `dur = clamp(dist*100, 450..2200) / _speedScale`（约 :3338），**由空间距离决定，与执行耗时无关**；
- `finishExecution()` 在拿到 `execute_done` 之后才调用 `driveTo(p, postDriveArrival)`——时序上是「工作完成 → 播放行驶 → 到达广播」。

**判据映射**：学科 2 检验问题 B1（路径位移是否对应真实工作）；双向断链的残留形态——
执行期间用户看到的是 token 文本流（真信号，P1 ✓），但**空间位移仍是与工作解耦的动画**。
剧场拆掉了，「位移 ↔ 工作」的对应关系尚未建立。

**建议**：行驶进度绑定真实执行事件——`execute_ack`/首 token = 起步，token 流 = 巡航推进，
`execute_done` = 落位停靠；执行慢则车慢，中断则车停在半路（与中断第三态天然契合）。
第一步从提问点开到候选点也应有行驶。改动触碰相机公式红线，须按不变量回归全套。

**关联**：这是「驾驶」隐喻从比喻变为度量的关键一步；M2 的 B0/B1（3D 联动单归因）实验解释力也依赖它。

## FI-02 🔴 `max_tokens=220` 硬上限：交付物被拦腰截断

**现象（实测）**：两次要求写 150–200 字说明，真实输出分别停在「天气概」「以」等句子中间；
到达牌照常宣告「这一步做完了」。

**代码定位**：`backend/task_tracker.py` `_llm` / `_llm_stream` 默认 `max_tokens=220`，
execute 主链调用写死 `max_tokens=220`（约 :756）。未见对 `finish_reason=length` 的检测与标注。

**判据映射**：**P0 结果可用性 / P2 可核对**——起草类任务的产物本身不完整，
「完成」宣告与产物状态不符。`judge_completion` 判达成度，但截断不被视为未达成。

**建议**：按任务类型配置上限（起草类 ≥1024）；捕获 `finish_reason=length` 时如实标
「输出被截断」并提供「继续生成」，不得无声交付半截产物。回归：截断场景的任务条/结果卡/账本三处一致。

## FI-03 🟠 探索环推演永远是本地模板：「下一方向」结构性不问模型

**现象（实测）**：两轮旅程中未来路牌凭据始终为「本地预览」；换模型、等空闲均不升级。

**代码定位**：`index.html` `autoExploreNext()` 写死 `&fast=1`（约 :6875）→ 后端
`get_forecaster(fast=True)` 纯本地实例。这是 v0.9.22 为避开 35B 单槽 20s+ 排队的成本决策
（见 CHANGELOG），v0.9.5 曾有的「fast 立牌 + 完整推演延迟精修」机制已移除。

**判据映射**：学科 1 在探索环缺席——「走完一步，前方长出扎根会话的新方向」这一核心承诺，
目前由关键词模板兑现。诚实标注解决了「冒充」（P1/P3 ✓），没解决「断链」。

**建议**：恢复异步精修——fast 秒级立牌，模型空闲时后台完整推演，回来后升级牌面并如实换标
（升级前用户已选路则作废，沿用 v0.9.5 的作废判据）。多端点/多槽环境下可直接并发。

## FI-04 🟠 长指令句下业务短语抽取产出碎片路牌

**现象（实测）**：输入「写一段150字左右的产品说明…」，路牌出现「**拆解字左右**」；
另见「检索一个天气应用首页写一段」动词短语粘连。短主题句（如「电力市场交易」）表现正常。

**代码定位**：`forecaster/llm_forecaster.py` `_extract_business_phrases()`（v0.9.24 引入）
按虚词/疑问词切分，对长指令句会把数量词残片、动宾半句当业务对象。

**判据映射**：路牌即认知（设计原则 #7）；P4 的可感知前提是牌面可读可信。

**建议**：抽取结果加质量门（最短长度、含数量词/单位残片则弃、动词开头则弃），
不合格走既有诚实分支「未取到具体业务对象」，不硬铺。补 `test_topic_binding.py` 长句用例。

## FI-05 ✅ 已修复（v0.9.49.3）前端硬编码 `localhost:8770`：不可部署、不可远程实验

**现象（实测）**：后端 `PORT` 改端口后前端立刻失联；无法置于反代/域名/局域网后供被试远程访问。

**代码定位**：`index.html` 共 6 处硬编码——`WS_URL`（:2463）、health（:2939）、
forecast（:3472、:6875）、journeys（:5276、:5316）。

**判据映射**：工程约束；M2 若需远程/多机被试则升级为阻塞项。

**建议**：REST 改相对路径；WS 由 `location` 推导（`wss:` 随 `https:`）。零配置，向后兼容本机场景。

## FI-06 ✅ 已修复（v0.9.49.3）健康探针对 Ollama 报 `llm_service: unknown`

**现象（实测）**：Ollama 正常出 token，`/api/health` 仍报 unknown，误导排障。

**代码定位**：`backend/server.py` `health()` 只探 `/status`（strata）与 `/health`（llama.cpp），
Ollama 健康端点为 `/api/tags`（OpenAI 兼容层无 /health）。

**建议**：探针链追加 `{base}/models`（OpenAI 标准，Ollama/vLLM/云端通吃）；README 已推荐
Ollama 为低门槛路径，探针应跟上。不消耗推理槽。

## FI-07 🟡 生产页面暴露可伪造 `source=llm` 的测试钩子

**现象（实测）**：`window.__cockpit.simulateArrival()` 默认参数即 `source:'llm'`，
在正常页面控制台可直接造出「模型完成」的到达与账本记录。本次差点将其截图误当实跑发布（靠图注核对拦下）。

**判据映射**：与 P1 诚实性纲领自相矛盾的隐患——系统红线是「不伪造来源」，
却留着默认伪造 llm 来源的公开钩子。

**建议**：钩子仅 `?test=1` 挂载；或模拟路径强制第五态 `source:'simulated'` 并在凭据条显式标注。
既有测试脚本同步加参数，回归零回退。

## FI-08 🟡 界面仅中文，与六语仓库门面脱节

**现象**：README/研究概要已六语（2026-11-22），但 HUD、凭据条、按钮、结果卡、toast 全中文；
外语读者克隆运行后无法使用。宣传触达人群与可用人群不重合。

**建议**：UI 文案层 i18n（字典 + `?lang=` / navigator.language 探测），至少覆盖
HUD/凭据/按钮/状态词；路牌与产物内容来自模型，随提示词语言走，不在 UI 字典范围。
术语沿用 [i18n/GLOSSARY.md](i18n/GLOSSARY.md)。

## FI-09 🟢 体验层两小项

- **无触屏等价通道**：出发靠双击、选路靠射线拾取；键盘等价视图（v0.9.19）已做，
  触屏/移动端核心交互不可用。建议单击选中 + 卡片「出发」按钮已有路径上补触屏手势门控。
- **单槽等待感知弱**：`_wait_strata(12s)` 等槽期间仅 4.5s 后一条「模型正忙」toast；
  小模型环境不明显，回到 35B 单槽将高频出现。建议等槽即在任务条如实显示「等待推理槽」及已等时长。

## 总评（用项目自己的尺子量）

**P1 真实性 ✓、P3 归因 ✓（路线 B 修复成立）；P2 有截断硬伤（FI-02）；
「语义空间改变 × 路径空间位移」的联合判据在行驶动画（FI-01）与探索环（FI-03）两处未闭合。**

换言之：剧场已拆，但「驾驶」目前 = 完成后的过场动画 + 本地模板铺的下一段路。
离「每一步位移都有真实工作作证」的愿景，差距集中在 FI-01 / FI-03——
建议作为 M2 实验前的优先修复项（FI-01 触碰相机红线，须全量不变量回归；
若 M2 按期开跑，至少在协议中记录 FI-01 为已知限制，避免 B0/B1 结论过度声称）。
