## 1. 要检验的命题（来自 RESEARCH-PLAN §1）

- **H2.1**：执行层已真实推进（P1 满足）的前提下，补上 P4 呈现（结果卡 + 可核对产物 + 归因）的组，实质进展感显著高于不呈现组。
- **H2.2**（镜像）：仅补呈现、执行层未真实推进时，进展感不应真正上升（C 组入口已落地，见 §2c，`?mode=decorative`）。

主指标 = s5（总体实质进展感）；机制指标 = s1–s4（逐一对应 P1–P4）。

## 2. 设计：2×1 被试间

| 组 | 执行层 | 界面呈现（原型入口） | 检验 |
|----|--------|----------------------|------|
| **A 对照组（执行不透明）** | 真实完成任务（与 B 同量） | `http://127.0.0.1:8770/?mode=opaque`：只显示「思考中…」流动动画 + 结束「已完成」；隐藏结果卡 / 可核对凭据 / 对比 / 时间线 / 风景来源 | H2.1 基准 |
| **B 实验组（执行透明）** | 真实完成任务（与 A 同量） | `http://127.0.0.1:8770/`（v0.9.20 默认）：结果卡 + 执行凭据 + 候选对比 + 时间线回看 + 风景来源 + 内部状态指纹环（v0.9.42 起） | H2.1 正向 |
| **B2 指纹环关闭组**（v0.9.43，手动） | 真实完成任务（与 B 同量） | `http://127.0.0.1:8770/?mode=no-fingerprint`：与 B 逐项一致（含账本 `internal_state`），**仅隐藏 3D 指纹环**这一路呈现 | 指纹环单变量对照（§2d） |

- 两组执行层**都真实推进**（路线 B 已落地，P1 满足），唯一差别是 P2/P3/P4 呈现 → 组间差异只能归因于「呈现」而非「执行更多」。
- 随机分配：`tools/m-instrument.html` 在知情同意后用 `Math.random()<0.5` 决定 arm（A/B 二分），并把对应 URL 展示给被试，不告知「哪组更好」。B0/B1/C/B2 均**不进随机池**，仅实验员手动覆盖。

### 2b. 最小对照 B0/B1（3D 联动单归因，已落地）

| 组 | 唯一差异 |
|----|----------|
| B0 | 同套结果卡，但结果卡**不**与到达节点 3D 联动（点定位按钮无 3D 响应、到达牌持续发光门控关闭） |
| B1 | 同套结果卡，**与**到达节点 3D 联动（F3.2 双向锚定，即 v0.9.28 现状） |

B1−B0 差异只能归因于「3D 联动」本身。**B0 已于 v0.9.28 落地**：原型加 `?mode=transparent-nolink`，仅隐藏 `.rc-locate-btn` / `[data-act="3d"]`（CSS）与 `focusArrivalIn3D` / 到达牌持续发光（JS 门控 `window._transparentNoLink`），结果卡本身与其他 P2/P3/P4 呈现层保留。回归脚本 `test_transparent_nolink.js`（6 项）。

### 2c. H2.2 镜像组 C 组（只呈现、执行未真实推进，v0.9.32 已落地）

| 组 | 呈现层 | 执行层 | 检验 |
|----|--------|--------|------|
| **C 镜像组** | 与 B 组**逐像素一致**（结果卡/凭据/对比/时间线/风景/3D/P0 工具全保留，CSS 不隐藏任何元素） | **本地伪执行**：不发 `execute`/`refine` WS、不调 LLM、不占模型槽；伪造逐字 token 流 + 完成回执，走 `handleWsMessage` 同一协议路径 | H2.2：若 C 组 s5 与 B 组无显著差异，说明「只补呈现」即可虚高进展感 → 呈现层本身在制造假象；若 C 显著低于 B，则真实执行是必要成分 |

- **入口**：`http://127.0.0.1:8770/?mode=decorative`（`window._decorativeMode=true`，`html.mode-decorative`）。实现见 `index.html` 检索 `DECORATIVE-MANIPULATION ZONE`；回归 `test_decorative.js`。
- **数据诚实（关键）**：伪执行的 `detail.exec.decorative=true` 正交标记，`source` 仍为 `llm`（呈现一致所需，否则 C 组与 B 组视觉不同会破坏操纵）。导出 JSON/CSV 含 `exec_decorative` 列与 `summary.exec_decorative` 计数；成品 .md 带「演示模式/本地模拟」水印。**研究分析必须用 `decorative` 标记把这些轮次单列，绝不计入 P1 真实执行结论；不得用 C 组数据声称执行真实。**
- **与 A 组差异归因**：A（opaque）隐藏呈现、B/C 呈现相同 → B−A 归因于呈现层有无；C 与 B 呈现相同、执行一真一假 → B−C 归因于执行真实性。两个对照分离 H2.1（呈现效应）与 H2.2（执行真实性效应）。
- **伦理（deception）**：C 组对被试隐瞒「执行为模拟」，属社会心理学标准 deception 设计。采集工具 `m-instrument.html` 中 C 组**不进随机池**（随机仍 A/B 二分），仅实验员手动覆盖选用；须在知情同意中概括告知「部分条件下系统行为可能被模拟」，任务结束后 **debrief 告知真实分组与模拟性质**。记录 `arm=C`、`arm_override=true`，分析时单列。

### 2d. 内部状态指纹环单变量对照 B2 组（v0.9.43 已落地）

背景：方向③把真实 MoE 聚合专家分布编码成 v0.9.42 的 3D 指纹环（吸附「现在」节点、可点展开 512 维直方图）。要检验的是**这一路真实内部状态信号的呈现**是否提升「实质进展感」，而不是重新检验整个 B 包。故设 B2 与 B 的单变量对照。

| 组 | 指纹环 | 账本 `internal_state` | 其余呈现 | 执行层 |
|----|--------|----------------------|----------|--------|
| B | 显示 | available（真采集） | 与 B2 完全一致 | 真执行 |
| B2 | **隐藏** | available（真采集，仍如实记账） | 与 B 完全一致 | 真执行 |

- **入口**：`http://127.0.0.1:8770/?mode=no-fingerprint`（`window._noFingerprint=true`）。实现见 `index.html` 检索 `no-fingerprint`；门控只跳过 `_fingerprintRing` 生成块，**不 return**，后续铺路/直道逻辑照常；`internal_state` 仍随 detail 进账本。回归 `test_no_fingerprint.js`（8/8：B 有环 / B2 无环、forkTopology 完全一致、B2 账本 internal_state 仍 available、0 JS 错误）。
- **归因**：B−B2 差异只能归因于「3D 指纹环有无」——执行层、账本数据、机位、轨道、到达牌、其余 P2/P3/P4 呈现全部逐项相同。这是比 B−A 更窄的单变量检验，专门回答「真实内部状态信号值不值得呈现」。
- **伦理（非 deception）**：B2 只隐藏一路装饰性内部状态呈现，**不隐瞒执行层**（仍真调模型、真记账），不属 deception，不触发 debrief 流程；知情同意无需「行为可能被模拟」告知。但**不进随机池**（随机仍 A/B 二分），仅实验员手动覆盖，记录 `arm=B2`、`arm_override=true`，分析时单列。
- **诚实边界**：f1 题项只问「是否看到内部状态线索及感受」，不问「能否读懂某专家含义」——专家 ID 是训练涌现的无名 ID，不能诱导被试报告不存在的可解释性。B2 保留 2D 账本 `internal_state` 凭据，故**单变量仅指 3D 环有无**，B−B2 差异不得外推为「去掉全部内部状态呈现」的效应。

## 3. 变量与操作定义

- **自变量**：界面呈现方式（透明 vs 不透明；另含 B0/B1 3D 联动、B2 指纹环有无两个更窄的单变量对照）。
- **因变量**：s1–s7 李克特（1=完全不同意 … 7=完全同意）。s1–s5 测「进展是否真实」，s6–s7 测「结果是否有用」（v0.9.30 P0），二者正交。
  | 条目 | 判据 | 测量 |
  |------|------|------|
  | s1 我相信这一步真正推进了我的任务 | P1 | 是否相信发生真实改变 |
  | s2 我能确认结果是真实可核对的 | P2 | 是否看到/能验证产物 |
  | s3 我知道是哪一步/谁带来这个改变 | P3 | 归因清晰度 |
  | s4 我在界面上注意到了这个改变 | P4 | 呈现可感知性 |
  | s5 整体上我感到产生了实质进展（而非只是看起来忙） | 总体 | 主指标 |
  | s6 我拿到了一份能用（可复制/导出/继续深化）的成果，而不只是一段摘要 | P0 | 结果可用性 |
  | s7 我清楚知道这个任务目标到底算不算达成 | P0 | 达成度可知 |
- **控制变量**：任务内容（同批任务、顺序随机）、执行层真实工作量、被试类型、视觉风格（A 组用同一套视觉，仅不呈现实质内容，剥离「新鲜感」）。
- **额外行为记录**（§5 量表外，客观佐证）：① 能否找到产物 ② 能否指出对应步骤 ③ 能否复述一条可核对依据 ④（v0.9.30）能否把成果带走（复制/导出）⑤（v0.9.43）是否注意到指纹环 `fp_noticed`（仅 B/B2）。
- **指纹环专项量表（v0.9.43，仅 B/B2 作答）**：与 s1–s7 主量表**正交且独立**，不与历史数据混算（非 B/B2 记录这些字段写 null，分析按缺值处理）。用户选「主量表+专项题」方案——s1–s7 一字不动，另加三题：
  | 条目 | 指向 | 测量 |
  |------|------|------|
  | f1 我看到一条能反映「系统内部如何处理」的线索（如放射状指纹环） | P4-内部 | 信号可感知性 |
  | f2 这条线索让我更相信这次执行是真的在计算，而不是装样子 | P1-信任 | 真实感提升 |
  | f3 这条线索帮我理解「上一步是怎么走到这里」 | P3-追溯 | 归因清晰度 |
  - 诚实边界：只问「是否看到线索及感受」，不问「能否读懂某专家含义」（专家 ID 无名，避免诱导不存在的可解释性报告）。
  - 判读：B2（无环）f1 应显著低于 B；若 B 的 f1/f2/f3 高于 B2，说明真实内部状态信号呈现确实贡献了 P4/P1/P3；若 B−B2 在 s1–s7 无差异而 f 题有差异，说明效应局限在「内部状态线索」这一子维度，不外推为总体进展感。
- **P0 与 H2 的关系（诚实标注）**：A 组（`?mode=opaque`）隐藏结果卡，因此 P0 工具（复制/导出/展开/达成度）在 A 组不可用是**呈现层差异**的一部分，符合 H2.1「唯一差别是呈现」的归因范围；但 P0 的「展开完整成果」是真实二次 LLM 生成，A/B 差异同时包含「能否用上 P0 能力」，分析时须把它与纯 P4 视觉呈现差异分开标注（对应 M3-ACCEPTANCE.md §2 的 H2.1 行）。

## 4. 任务脚本（满足 M0 任务设计要求：双类型 + 缺数据版）

每个被试随机抽 1–2 个任务；同组内任务顺序随机。任务原文直接粘进原型输入框。

### T1 起草类（草稿即产物，验证 P2 成立路径）
> 任务：国内电力交易市场的格局？先「查资料」摸清现状，再「对比分析」主要模式，最后挑一条方向「重走」一次看真实结果。

### T2 数据分析类（必须附输入数据，验证 P2 可核对）
> 前置：实验员把 `tools/sample-data.csv`（样例：某省 12 个月发电量/负荷/电价）贴给被试。
> 任务：基于这份给定数据，找出 1–2 处异常波动，并指出你判断的依据。

### T3 数据分析类 · 缺数据版（检验路线 B 的 P2 边界）
> 任务：基于我们的销售数据，找出异常并指出依据。（实验员**不提供**任何数据）
> 观察点：界面能否准确传达「缺少输入」而非编造具体数字结论。

> 三类任务的差异正是 M0 任务设计要求：T1 让 P2 有成立路径；T2 让 P2 有可核对依据；T3 检验「无输入时界面是否诚实」。实验记录须标注 `task_type ∈ {draft, data_with_input, data_missing_input}`。

## 5. 程序时间线（每被试）

1. **知情同意**：说明研究目的、数据仅本地留存、可随时退出（见 §10）。
2. **随机分配**：instrument 决定 arm，展示对应原型 URL + 本次任务脚本。
3. **出声思维（think-aloud）**：被试边操作边说「现在在想什么 / 觉得它做了什么」。实验员不打断、不提示。
4. **任务执行**：被试在原型完成分配的任务（可多轮）。
5. **量表填写**：任务结束后在 instrument 填 s1–s7 + 行为结果（4 项 + B/B2 的 `fp_noticed`）+（仅 B/B2）指纹环专项 f1–f3 + 定性备注。
6. **简短访谈（Q1.2 归因）**：追问「你说没/有进展时，指的是 P2 看不到产物、还是 P3 说不清谁做的、还是 P4 没注意到？」——直接回答 PROBLEM.md §6 的缺口。

## 6. 数据采集工具（`tools/m-instrument.html`）

纯前端、可 `file://` 直接打开、无需服务器。流程：知情同意 → 随机 arm（A/B 二分，B0/B1/C/B2 手动覆盖）→ 展示 URL+任务脚本 → s1–s7 李克特 →（B/B2）指纹环专项 f1–f3 + `fp_noticed` → 行为结果 → 定性备注 → **按参与者自动生成 M3 清单草稿** → localStorage 批量暂存 + 导出 JSON/CSV。

- 每条记录字段见 §7 schema。
- 导出 CSV 含 BOM，逗号/双引号/换行按 RFC 转义，可直接进统计软件。
- v0.9.43 数据完整性：① `PROTO_VER=v0.9.43` 写入每条记录；② 专项卡片与 `fp_noticed` 仅 B/B2 显示，其它组写 null；③ 「下一位被试」复位所有 radio 选中态，防同一浏览器连续记录时残留污染 B2 对照；④ 提交校验：B/B2 必须答完 s1–s7 + f1–f3 + `fp_noticed`。

## 7. 数据 schema（每条被试记录）

```
pid            string   随机或录入的唯一编号
arm            'A'|'B'|'B0'|'B1'|'C'|'B2'   (C=H2.2 deception 镜像组见 §2c；B2=指纹环关闭单变量对照见 §2d；均单列分析、不进随机池)

f1..f3         int 1..7 | null  指纹环专项（P4-内部/P1-信任/P3-追溯，v0.9.43；仅 B/B2 作答，其它组为 null=缺值）
fp_noticed     bool | null      是否注意到指纹环（v0.9.43；仅 B/B2 作答，其它组为 null=缺值）
found_product  bool    能否找到产物
named_step     bool    能否指出对应步骤
recited_evidence bool  能否复述一条可核对依据
took_result    bool    能否把成果带走（复制/导出，v0.9.30；老记录可能缺失）
think_aloud    text    出声思维转录/摘要
interview_note text    Q1.2 归因访谈
notes          text    其他
prototype_ver  string  'v0.9.20' / 'v0.9.30'（含 P0）/ 'v0.9.43'（含指纹环专项 f 字段）
ts             ISO8601 填写时间
```

## 8. 统计与诚实标注（沿用 RESEARCH-PLAN §3.5）

- n<5/组：不做显著性声明，只报方向 + 明确「样本不足」。
- 被试为代理（开发/同事）：结论标注「代理被试，待真实用户确认」。
- 主分析：s5 组间差异（Mann–Whitney U 或 Welch t，按分布选）；机制看 s1–s4 哪一维在 B 组显著抬升（预期 s2/s3/s4）。
- 行为结果作客观佐证：B 组 found_product/named_step/recited_evidence 应高于 A。
- **指纹环单变量分析（B vs B2，v0.9.43）**：两组的 s1–s7 与 4 项通用行为结果应无系统差异（执行层/其余呈现相同），差异只应落在专项 f1–f3 与 `fp_noticed`——预期 B 组 f1 显著高于 B2（B2 无环、f1 应接近 1）、B 组 f2/f3 若高于 B2 则说明真实内部状态线索对信任/追溯有贡献。样本不足（n<5/组）只报方向。⚠️ B/B2 都是手动覆盖组（`arm_override=true`），存在实验员选择偏倚，结论须标注；不可与随机 A/B 组混池做主效应检验。
