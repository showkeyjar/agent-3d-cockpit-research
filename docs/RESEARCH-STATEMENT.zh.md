# agent-3d-cockpit-research

> 智能体 3D 驾驶舱中「实质性进展」的感知与度量 ——
> 一个**跨学科研究项目**：向量空间上下文可视化 × 3D 路径空间人机交互展示。

## 这是什么

本项目是 [agent-3d-cockpit](C:/Users/smith/WorkBuddy/2026-11-03-19-18-08/agent-3d-cockpit) 原型（本地绝对路径，跨盘相对路径会失效）的**研究背书**，不是它的开发主线。原型可访问入口：`http://127.0.0.1:8899/index.html`（静态）或 `http://127.0.0.1:8770/`（后端直出）。

本研究横跨**两个学科**（详见 [docs/SUBDISCIPLINES.md](docs/SUBDISCIPLINES.md)）：
- **学科 1 · 向量空间上下文可视化**：智能体上下文中语义结构的真实变化（候选采样、分桶、方向分化）如何被感知与呈现——载体：`forecaster/`。
- **学科 2 · 3D 路径空间人机交互展示**：智能体工作以 3D 路径空间承载时，路径中的"前进"什么时候是实质位移、什么时候是视觉表演——载体：`index.html`。

两个学科交叉于一个公共度量：**实质进展 = 语义空间改变 × 路径空间位移联合成立**（P1–P4 联合判据）。

原型从 v0.9.6（2026-11-06）到 v0.9.9（2026-11-09）做了四轮迭代，集中在「岔口／候选的呈现层」：
- v0.9.6 候选数透传（要 5 给 5）
- v0.9.7 多智能体预览车队（岔路同步派出小车）
- v0.9.8 沉浸形态（I 键沉浸 + V 键立体 + WebXR 预留）
- v0.9.9 语义分桶（同义簇折叠，候选间真正不同的方向）

但用户在使用后给出的核心反馈是：**「界面上感觉没有实质性进展」**。

呈现层的精细化已经越过收益拐点——继续在 3D 视觉和候选排版上打磨，是属于「拍脑袋继续开发」的路径。本研究项目要做的，是回答一个排列在呈现层之前的问题：**什么才构成这个驾驶舱的「实质性进展」？它在界面上如何被感知、如何被度量、如何被设计出来？**

## 为什么需要它（而非继续开发）

不是所有「用户觉得不够好」都该靠加功能解决。当反馈重复出现、而每次的迭代口径都还在上次的层面时，说明缺的不是新的可交付特性，而是对「好」的定义做一次校准。

这里有一个可检验的模式：
- 四轮迭代的交付物都是**呈现层**（视觉、数量、语义）。
- 用户说「没有实质性进展」——进度感知指向的是**执行层**（实际做了什么、改变了什么、验证了什么）。
- 呈现层做到位，执行层没跟上，进度感知就停在「看起来动，实际上没动」。

所以下一步开发若要成立，必须先回答：实质性进展≠看着丰富，得是**执行链对真实任务有真实的推进**，且这个推进在界面上可见、可验。

## 怎么用

研究产出**不是**直接改原型。它的用法是给后继开发一个「先自检再动手」的站台：

1. 每次开发先问：推进的是哪个学科的哪个维度？
   - 学科 1（向量空间）：这一次改变了**语义结构**的什么？（方向数 / 簇 / 方向间距离）
   - 学科 2（路径空间）：这一次改变了**路径位移**的什么？（真实性 / 可追踪性 / 沉浸效应）
2. 单独推进一门学科而不提升联合判据 P1–P4 → 默认视为「未构成实质进展」，需给出理由（防"又一种做了看不见"）。
3. 每个里程碑用 Q4 的联合量尺验收，而不是用「看起来好了」。

## 定位补记（2026-11-24）：可视化 = 思考辅助工具

用户新认识：**「这种可视化更多可作为思考的辅助，一个想象力激发工具，或者一个思维导图生成工具？」**

### 1. 三个说法是同一件事：把思考外化

| 说法 | 对应功能 | 认知机制 |
|------|----------|----------|
| 思考辅助 | 把选择空间、执行历史、上下文视野放到外部，不必记在脑子里 | 减轻工作记忆负荷 |
| 想象力激发 | 并置未走的路（候选分叉），让人看到没想到的方向 | 扩展搜索空间 |
| 思维导图生成 | 把语义拓扑（共干 → 簇分叉 → 候选细枝）变成可导航的空间 | 结构化外化 |

共同点：可视化的价值不在「呈现进度」，而在**让用户看见自己正在想什么**——是外化认知（external cognition），不是进展证明。

### 2. 与「四轮呈现层无效」不冲突：目标函数不同

四轮迭代（v0.9.6–9）无效，是因为它们的目标是「让用户相信有进展」——那是**执行层**的工作，呈现层做不到，所以它失败了。
新定位下呈现层不再冒充执行层，只做它真正擅长的事：外化思考。**这不是回到老路，是换了一个可达成的目标函数。**

### 3. 已有机制盘点（新定位不是从零开始）

| 已有机制 | 版本 | 在新定位中的角色 |
|----------|------|------------------|
| 语义树状分叉（共干 → 簇分叉 → 候选细枝） | v0.9.38 | 思维导图骨架：把选择拓扑外化 |
| 候选并排只读（C 键） | v0.9.19 | 想象力激发：看见没选的路 |
| 2D 会话脉络视图 + `buildSessionDigest()` | v0.9.37 | 思考轨迹外化 |
| `digest_kept_seqs` 只读投影 | v0.9.44 / Q-d | 让「模型视野边界」可追溯 |
| 结果牌 / 四态账本 / 来源四态 | P0–P4 | 思考的锚点：可核对的事实 |

→ `docs/CROSS-TURN-PROGRESS.md` §7 的 **Q-b（衰减可视化：显式标出哪些轮已不在模型视野内）** 正是新定位的第一个具体落点：让用户知道模型「忘了什么」、要不要重提。

### 4. 边界（纪律，勿越）

- **不推翻 P0–P4**：诚实性底线不变，思考辅助的前提是不误导（不伪造进度）。P0 结果可用性仍是北极星。
- **定位 ≠ 结论**：这是研究方向假设，不是已验证的用户收益。原假设问「呈现能否提升进展感」，新定位问「外化能否提升决策质量」——因变量变了，需要新证据。
- **不做问卷量化困惑**（用户 2026-11-23 已否决该路线）：验证应用客观行为指标（是否选了此前没考虑的方向、跨轮回溯次数、任务完成时间），而非主观量表。
- **四轮无效的前车之鉴仍有效**：任何「让画面更丰富」的改动，必须先回答「它外化了什么信息」——答不出就不做。
