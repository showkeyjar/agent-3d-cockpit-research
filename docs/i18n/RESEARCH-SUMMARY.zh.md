## 研究问题

在一个用 3D 驾驶舱呈现智能体工作的界面里，用户在什么条件下能感知到「实质进展」而非「形式进展」？

起点是一句真实用户反馈：**「界面上感觉没有实质性进展。」** 此前四轮迭代（候选数量、预览车队、沉浸立体、语义分桶）全部落在呈现层；第五次反馈越过呈现层，指向执行层。

## 工作定义：P1–P4

实质进展 = 界面让用户感知到「用户的某个真实任务状态，因智能体的工作，发生了可核对、可追溯的改变」。四条判据缺一即退化为形式进展：

- **P1 真实性**：改变发生在真实任务/产物上；
- **P2 可核对**：用户能自己确认改变是真的；
- **P3 可追溯**：能知道是谁/哪一步带来的改变；
- **P4 可感知**：改变在界面上可被认出。

## 关键发现：中间剧场 + 尾部真实

静态审计（AUDIT.md）发现旧执行链中间步骤不调用 LLM：`prompt` 是死参数、进度由 `asyncio.sleep(0.09)` 驱动、中间产物是模板句。运行时实证（RUNTIME-AUDIT.md）用 WebSocket 计时钉死：`task_update` 间隔整齐 90–100ms、零散布——sleep 的指纹；该记录中假节拍约占总时长 86%（仅该记录的诊断数字）。只有最后一步 output 是真实 LLM 调用。

这证伪了「有进展但没呈现」的乐观假设：问题首先是 P1/P3（真实性与归因），其次才轮到 P4（呈现）。

## 修复：路线 B（诚实降级）

删除全部剧场中间步骤，收敛为单步真实 LLM 流式调用；进度 = 真实输出字数；归因链 `["output"]` 与事实一致。复测：整齐节拍指纹消失，token 流覆盖执行时长 60–70%。

**边界**：路线 B 修复 P1/P3，不自动修复 P2——数据分析任务若无输入数据，模型生成的具体数字不可复算，P2 不成立。界面须如实呈现「缺输入」而非编造结论。

## 学科框架：双向断链

- 学科 1（向量空间上下文可视化）：语义结构真实改变（分桶/方向分化），但曾在路径空间无可感知差异；
- 学科 2（3D 路径空间 HCI）：呈现丰富（车队/沉浸/立体），但「前进」曾无真实位移支撑。

两学科互不作证 = 双向断链，是「没有实质性进展」的机制假说（待真人实验验证）。

## 实验计划

M1 装置已就绪：A/B（执行不透明 vs 透明）、B0/B1（3D 联动单归因）、B2（指纹环单变量）、C（装饰性伪执行镜像组，含 debrief）；三类任务（起草 / 附数据分析 / 缺数据分析）；s1–s7 + f1–f3 量表。**M2 真人对照与 M0 出声思维待执行**；所有真人判据在数据进来前保持待验，不得宣布完成。

## 证据纪律

四级证据：静态代码审计 → 运行时实证 → 代理被试 → 真人被试。样本不足只报方向不做显著性声明；代理被试结论降级标注；开发侧观察不冒充用户侧结论。
