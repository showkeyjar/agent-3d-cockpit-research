# 探针报告：把推理模型的实时激活映射到 3D 空间

> 状态：**隔离式技术探针已完成（2026-11-19）**。结论是「技术上可行，但直接做法的证据不足，不应直接进主线」。
> 触发：用户提议「把当前推理模型正在激活的权重实时映射到 3D 空间，省掉风景计算」。
> 方法：隔离实验——独立源码副本 + 独立二进制 + 独立端口（8090），全程未触碰 8083 主力服务。
> 纪律：本报告严格区分【已验证】/【初步证据】/【理论动机】，不把初步证据写成结论。

---

## 0. 先纠正提议里的两个概念

1. **权重是静态的**，没有「正在激活的权重」这回事。推理时真正流动的只有三样东西：MoE 路由决策（选了哪些专家）、attention 图、hidden state 幅值。可映射的是这些**激活量**，不是权重本身。
2. **「省掉风景计算」这个理由不成立**。当前语义风景是浏览器里对上下文文本做哈希、抽概念短语铺成 3D 点——纯前端、几乎零成本。真实激活可视化反而**更贵**（见 §4 代价）。这条路的价值若成立，也只可能成立在 P1 真实性升级上，不在省算力上。

---

## 1. 探针要回答的两个问题

| # | 问题 | 判据 |
|---|---|---|
| Q1 | 技术上能不能从 llama.cpp 拿到**真实**的逐 token 激活数据？ | `/experts` 返回真路由张量，非模拟 |
| Q2 | 拿到后，人能不能从中读出**稳定的语义/决策依据**？ | 同一任务重复的自相关显著高于不同任务互相关 |

**Q1 是工程问题，Q2 才是决定它是不是「实质进展」的研究问题。** 整个项目的核心命题（P1–P4）要求：可感知之前先可核对、可追溯。一团随 token 抖动的粒子云即便真实，也只是「真装饰」。

## 4. 代价测量【初步证据，有噪声】

同一二进制、同一 prompt、同一采样参数，唯一区别是 `--expert-stats` flag（各 3 次，120 token）：

| 配置 | 吞吐 | 说明 |
|---|---|---|
| 开 `--expert-stats` | 33.9 tok/s（33.1 / 34.7 / 33.8） | eval callback 每层 device sync |
| 关（基线） | 45.6 tok/s（40.2 / 53.4 / 43.0） | `/experts` 返回 501，端点禁用 |
| **差值** | **约 -26% 吞吐** | callback 的纯代价 |

⚠️ **外推限制**：这是小模型（24 层 / top-4）+ Vulkan 单卡 APU 上的结果。第三方 patch 文档声称在双 GPU 大模型上只掉「几个百分点」。本机的 Vulkan 后端每层 device sync 相对开销更高，且开启实例是冷启动、基线是热启动（页缓存），测量有系统偏差。**不能把 -26% 直接当成 8083 主力（48 层 / top-10 / 36GB）的代价**，需要在目标模型上复测。但量级足以说明：这个代价不是免费的，且与层数正相关。

## 5. 可解释性实验【关键发现：逐 token 路由这条做法证据不足】

用语义差异明显的两组任务各跑一次，取各层最近路由的专家频率分布（60 维向量），算 Pearson 相关：

| 对比 | Pearson r | 解读 |
|---|---|---|
| 中文科普 vs 英文代码（不同任务） | 0.040 | 几乎零相关 |
| 中文科普 vs 英文代码（另一组） | 0.203 | 很弱 |
| **同一 prompt 跑两次（自相关）** | **0.293** | **关键对照** |

**判据**：如果专家路由编码了稳定的「任务语义」，那么同一任务的两次运行应该高度相似（自相关高），且显著高于不同任务（自相关 >> 互相关）。

**实测结果**：自相关 0.293 与互相关 0.203 差距很小。这说明路由模式的差异**主要来自 token 级随机性**（采样温度、具体生成内容），而非「模型正在用哪类专家处理这类任务」的稳定分工。

⚠️ **方法边界**：① 只用了小模型（60 专家 / top-4），其专家专门化程度本来就低；大模型（512 专家 / top-10）的专家分化可能强得多。② 补丁的路由窗口只有 `TAIL=16` 条，样本很小；③ 两次任务混在同一 256-token 窗口，n_tokens 从 117 跳到 218，采的是不同批次 token，含噪声。因此**不能据此断定「所有激活可视化都无语义」**，只能断定「逐 token 专家频率分布这条具体做法，在小模型上没测出稳定语义」。

## 6. 结论与建议

### 6.1 对原提议的裁决

- 「省掉风景计算」——**不成立**，真实激活更贵。
- 「把激活映射到 3D」——**技术上可行**（Q1 通过），但「直接映射逐 token 路由」这条做法**没有测出可解读语义**（Q2 未通过），且代价不低。
- 若按原样直接做，产出大概率是「一团随 token 抖动的真实粒子云」——P1 真实 ✓、P4 可感知 ✓，但 P2 可核对 ✗、P3 可追溯 ✗，正是本项目反复抵制的「真装饰」/新剧场。

### 6.2 若继续推进，更有希望的方向（均为【理论动机】，未验证）

1. **换信号源**：从「逐 token 路由」换成**跨 token 聚合的专家偏好**（整段回答结束后，各层专家的累积命中直方图）——它更稳定，但需要长窗口/全量统计，补丁当前只留 256 token 环形窗口，要改。
2. **在目标大模型上复测可解释性**：512 专家的专门化可能远强于 60 专家。**这是决定是否值得做的关键实验**，但要动 8083 主力或另起 36GB 实例（内存/加载风险高）。
3. **映射到结构而非粒子**：把专家偏好编码进已有的「语义树状分叉」拓扑（v0.9.38），让空间结构承载语义，而非自由粒子云。
4. **attention 图信号**：能看到模型关注了哪些 token，语义可名状性理论上强于专家 ID，但需 `--attention-output` + 降维，代价更大、实时性更差。

### 6.3 支柱性判断

**别把它当呈现层升级做。** 项目头号教训是「四轮呈现层迭代无效，根因在执行层」。激活可视化只有在挂到 P1–P3 真实推进上（用户能从中核对/追溯决策依据）时才成立；否则它只是用真数据演的新剧场。**Q2 未通过 = 现在还不满足这个前提。**
