# 跨轮次进展 · 研究设计（CROSS-TURN PROGRESS）

> 新研究主题（2026-11-19 立项）。把项目核心判据从**单轮**扩展到**多轮会话**。
> 定位：本研究不是修 bug，而是把一个此前只被当作"工程连续性"的现象，提升为可证伪、可度量的科学问题。
> 底座：v0.9.37 会话脉络工程（_runs 账本 / buildSessionDigest / sessionEvents / 脉络视图）+ v0.9.43 装置。
> 纪律：本文的【运行时】结论都是可复算的客观事实；**"用户是否真的感到跨轮次进展累积/断裂"属【真人】待验，不得混用**。

---

## 1. 为什么这是新问题

项目的核心命题是"实质进展感来自 P1–P4（真实性/可核对/可追溯/可感知），而非呈现层华丽度"。
但**现有全部判据都是单轮的**：一次提问 → 一次执行 → 一次 status/completion 判定。真实用户不是这样用的——他们连续多轮、补充约束、重走分叉、回头综合。

于是出现一个判据盲区：

> 单轮 P1–P4 全绿，**不代表跨轮次进展成立**。第 1 轮的真实结论可能在第 7 轮已经不在模型的语义上下文里，但账本里它还在、3D 轨迹里它也还在。用户到底"感到"进展累积了，还是每轮都像重开？现有框架答不了。

这正是 `docs/EVIDENCE.md §未决` 与 `docs/SUBDISCIPLINES.md §6`（Q1.2 补充 / Q2.2 / Q4）留下的"用户侧语义"缺口的一个可操作化切入点，且**不依赖真人就能先把度量造出来**。

---

## 2. 核心发现：三层不同步（可复算事实）

跨轮次信息在原型里存在三个"层"，它们的保真度**不一样**：

| 层 | 载体 | 累积策略 | 保真度 | 语义 |
|----|------|----------|--------|------|
| **账本层** | `_runs`（真相源） | 每次执行收尾追加一条；失败/中断/澄清也记；只追加不覆盖 | **完整**（N 轮全在） | 研究真相：发生过什么 |
| **轨迹层** | `journey`（3D 路径） | 走过即留，用户节点/分叉/到达持续累积 | **完整**（视觉连续） | 空间锚点：走到过哪 |
| **语义层** | `buildSessionDigest()`（进 LLM 上下文的历史摘要） | 只取最近 **6 轮**（`tail=6`），每轮结论截 **60 字**，只取一句话结论、不带 steps，用标记包裹供后端门控剥离 | **有损**（超出 6 轮即丢弃） | 模型视野：还记得什么 |

**关键含义**：第 1–3 轮的结论在账本和 3D 里都还在，但在第 7 轮的 LLM 语义上下文里已经被 `tail=6` 丢弃。即——

> **进展在账本里累积，在模型语义里衰减。** 这是设计权衡（防摘要膨胀 + 防历史数据词污染任务类型门控），不是 bug，但它产生了一个真实的科学问题：这种不同步会不会让用户感到"前面白做了 / 又从头开始"？

## 3. 可证伪研究问题与度量

### RQ1 · 进展是否跨轮累积？（累积性）
- **主张**：连续多轮真实执行后，后续轮次的语义上下文确实携带了前序轮的结论，而非每轮从零开始。
- **证伪条件**：digest 为空、或只含本轮原话、或不含任何前序轮的可识别结论。
- **度量 M2**：`buildSessionDigest()` 输出中"· 第N轮…"行的条数与内容。
- **现状（【运行时】）**：携带最近 6 轮真实结论，证伪条件**不成立** → 累积存在，但**有界**（6 轮封顶）。

### RQ2 · 断裂发生在哪一层？（定位）
- **主张**：跨轮断裂若发生，是可定位到具体层的，不是笼统的"上下文断了"。
- **证伪条件**：三层保真度相同（那就没有"哪一层"的问题）。
- **度量 M1/M2**：账本完整率 vs 语义保留率。
- **现状（【运行时】）**：注入 9 轮 → 账本 9/9、语义 6/9。**账本完整、语义截断**，断裂点定位在**语义层**，账本层与轨迹层不断裂。这修正了 v0.9.37 之前"上下文整段覆盖"的旧认知——那时是语义层**全断**，现在是**有界截断**（断了早期轮，保住近期轮）。

### RQ3 · 哪些轮配进"历史"？（语义诚实）
- **主张**：摘要只把"真实、完成、可核对"的轮次当作历史，不把模拟轮/综合轮/失败轮冒充成历史证据。
- **证伪条件**：decorative / synthesized / failed / local 轮进了摘要。
- **度量 M3**：注入四类非真实轮，检查摘要是否排除。
- **现状（【运行时】）**：四类全部排除；再注入后摘要仍是 6 条真实轮。**语义诚实成立**。

### RQ4 · 门控能否剥离历史而不污染本轮？（可追溯性边界）
- **主张**：摘要用专用标记包裹，后端任务类型门控可整段剥离、只看本轮原话——历史里出现的数据词不会把起草任务误判成分析任务。
- **证伪条件**：剥离后残留摘要文字，或剥离掉本轮原话。
- **度量 M4**：`_stripDigestForTest` 剥离后是否恰好剩本轮原话。
- **现状（【运行时】）**：剥离精确，本轮原话完整保留。**门控边界成立**（沿用 v0.9.37 的上下文污染防线）。

### RQ5 · 用户能否感知跨轮累积？（进展感——**真人待验**）
- **主张**：账本/轨迹的完整累积 + 语义层的近期累积，足以让用户感到"进展在积累"而非"每轮重开"。
- **证伪条件**：真人被试在多轮任务后仍报告"感觉不到前面的工作被记住/用上"。
- **度量**：需真人（M2 扩展）：多轮任务后的访谈题 + 脉络视图使用行为。
- **现状**：**【真人】待验**。运行时只能证明"信息在账本/摘要里"，不能证明"用户感到了"。⚠️ 不得用【运行时】的 M1–M4 结果冒充 RQ5 结论。

## 4b. Q-a 摘要保留策略离线对比（2026-11-19）

**问题**：`tail=6` 是否最优？"最近 N 轮 + achieved 里程碑永久保留"能否在可控膨胀下提升跨轮累积保真？

**脚本**：`prototype/test_digest_strategy_compare.js`（repo ↔ LIVE 同步），**16/16 通过**。纯离线策略对比、不碰生产默认值、不占模型槽。

**忠实性 golden 校验**（这是结论可信的前提）：先用真实账本对象跑离线模拟器，其 S1（tail=6）输出与真实 `buildSessionDigest()` **逐字相等**（`goldenMatchesSimulator=true`）——证明模拟器精确复刻了 `oneLineConclusion(30字)→slice(60)` / 方向 18 字 / completion 文案 / 标记包裹 / 干扰轮排除的全部逻辑。之后才用同一模拟器比较其它策略。

**决议数据**（12 真实轮：7 achieved / 3 partial / 2 need_input + 4 干扰轮全排除）：

| 策略 | 保留轮 | RQ1 recall | 里程碑保留 | 字符数 | 丢弃 seq |
|------|-------|-----------|-----------|--------|----------|
| S1 `tail=6` 生产基线 | 6 | 0.500 | 3/7 (0.43) | 302 | 1,2,3,4,5,6 |
| S2 `tail=3` 更激进 | 3 | 0.250 | 2/7 (0.29) | 152 | 1–9 |
| S3 `tail=12` 近全量 | 12 | 1.000 | 7/7 (1.00) | 602 | — |
| **S4 `tail=6`+里程碑永久** | 10 | 0.833 | 7/7 (1.00) | 502 | 3,5 |
| **S5 `tail=3`+里程碑上限6** | 6 | 0.500 | 5/7 (0.71) | 302 | 1,2,3,5,7,9 |
| S6 仅里程碑 | 7 | 0.583 | 7/7 (1.00) | 351 | 3,5,7,9,10 |

**结论（可复算）**：
1. **S5 是相对生产基线 S1 的帕累托改进**：完全相同的字符预算（302），里程碑保留 3/7 → 5/7，**零膨胀代价**换回 2 个早期达成轮。适合"不想让摘要变长"的场景。
2. **S4 信息最全但代价与隐患并存**：recall 0.5→0.833、里程碑全保，但 +200 字符（+66%）；更关键的是**无上限里程碑会随会话单调膨胀**——长会话（如 50 个 achieved）摘要会持续增长，违背 `tail=6` 当初"防膨胀"的设计初衷。
3. **S6 仅里程碑有语义风险**：351 字符保住全部里程碑，但丢掉了最近的 partial/need_input 轮（如 seq10）——这些恰恰是**当前任务上下文**，"只记成功不记待办"会让模型误以为历史任务全部完成。

**推荐（仅信息层，不改生产）**：若要调整，优先评估 **S5（有上限的里程碑增强）**——同等 token 成本下多保里程碑，且避免了 S4 的无界膨胀；S6 不单独采用（丢当前上下文）。**但本对比不直接触发改默认值**，理由见 §6 与 §7 Q-a 的诚实边界：是否调整须经真人 RQ5 验证进展感 + 门控污染复测双重确认。

**诚实边界**：
- 这是**摘要文本保留机制**的离线对比，用 `_injectExecuteDoneForTest` 注入账本，**不是真实多轮 LLM 交互**。
- 它回答"哪种策略在信息层保留更多"，**不回答**"用户是否因此感到进展累积"（H4.1 / RQ5 仍 [真人] 待验）。
- 里程碑轮仍带 `SESSION_DIGEST_*` 标记包裹、仍被后端门控剥离——增加历史轮**不会**重新引入任务类型污染（v0.9.37 门控纪律不回退）；但 prompt 侧历史背景词增多对生成质量的影响需真实交互验证。

## 4c. Q-d 跨轮语义衰减只读投影进账本（v0.9.44，2026-11-19）

**问题**：三层不同步是运行时事实，但账本里看不到"某轮是何时掉出模型视野的"。能否把这个衰减写进账本/导出，让 P3 的可追溯性扩展到多轮——且不算"新增完成信号"？

**判定：可以做，前提是纯派生只读投影。** 现有完成信号是 `status`（四态）+ `completion`（三态），它们**参与判定**（门控、达成度、主轴推进、M3 验收）。新增字段 `digest_kept_seqs` 的值完全由 `_runs` 内容 + 固定 `tail=6` 算法派生，**不参与任何判定路径**——性质等同 `internal_state_dist` / `forecast_divergence` 这类描述性元数据。没有新增完成信号，不破坏 P1 账本纪律。

**实现**（单一真相源，防逻辑漂移）：
1. 把 `buildSessionDigest` 的"真实轮筛选 + tail 截断"抽成共享纯函数 `digestRealRuns()` / `digestKeptSeqs()`——投影与摘要用同一套逻辑（也正是 Q-a golden 校验过的那套）。
2. 每条 run 在 `recordRun` 收尾时写 `digest_kept_seqs = digestKeptSeqs()`——记下"本轮结束时语义视野内有哪些真实轮 seq"。
3. JSON 导出全字段深拷贝自动带；CSV 增列 `digest_kept_seqs`（含逗号数组按 RFC4180 转义）。
4. 时序关键点：正交标记必须在 `recordRun` 时就位。真实路径均满足——synthesize 走 `onRefineDone`→`recordRun`（detail 自带 `synthesized`），decorative 经 `onExecuteDone` 透传。测试钩子 `_injectExecuteDoneForTest` 对 synthesized 是后补写（execute_done 协议本不带），故另加 `_injectSynthesizedForTest` 模拟真实路径。

**跨轮衰减可追溯性**（实测 9 轮，注入式）：
```
轮1 kept=[1] → 轮6 kept=[1..6] → 轮7 kept=[2..7]（seq1 掉出）→ 轮9 kept=[4..9]（seq1-3 掉出）
```
对比任意两轮的 `digest_kept_seqs`，即可定位某 seq 何时离开模型视野——**RQ2"断裂在哪一层"从"摘要文本里推断"升级为"账本字段里直接读"**。

**验证**：`prototype/test_digest_provenance.js`（repo ↔ LIVE 同步）**18/18 通过**：字段存在、逐轮演进（tail=6 边界精确）、干扰轮（decorative/synthesized/failed/空输出）全不进 kept、投影不改 completion/status、JSON/CSV 导出对齐（RFC 引号）、forkTopology 与 0 JS 错。关键回归 cross_turn 21/21 + session 31/31 + timeline 42/42 + synthesize 全过 + tree_fork 17/17 + no_fingerprint 8/8。

**诚实边界**：注入式账本，非真实多轮 LLM 交互；投影只记录"视野内 seq"，不度量用户是否感知（H4.1/RQ5 仍 [真人] 待验）。它让衰减**可追溯**，不等于衰减**被感知**。

## 4d. Q-c RQ5 真人协议与采集装置（2026-11-20，装置已备 / 数据待采）

RQ5（§3）是唯一无法用运行时探针回答的问题——"用户是否感到跨轮累积"。本节点备好**可执行协议 + 专用采集工具**，真人被试不可代做，但装置先就位。

### 埋锚点 → 跨 tail 边界回收（核心范式）

要让"语义衰减是否损害进展感"可证伪，协议必须让早期信息**掉出语义视野但仍应被感到**。设计 ≥7 轮脚本（跨 `tail=6` 边界）：

| 轮次 | 操作 | 观测点 |
|------|------|--------|
| R1 | 起草任务 + 设专属代号「青鸾计划」 | **锚点 A**（独特、非模板可猜） |
| R2–R3 | 对比模式 / 给专属数据集 + 判断依据 | **锚点 B**（具体异常与依据） |
| R4–R6 | 每轮追加新约束、不重复旧信息 | 中段推进；R4 起 R1 将出视野 |
| R7 | 提出需用到 R1/R3 结论的新问题（**不提醒**） | 进入 tail 边界 |
| R8–R9 | 要求按"之前定的代号"整理 / 引用前面异常分析 | **回收**：锚点是否被记住/接上 |

- **证伪逻辑**：若被试在 R8/R9 仍感到"前面工作被记住并接上"（r 量表高 + 主动回忆锚点），则 RQ5 倾向成立；若普遍报告"每轮像重开 / 得重新输入代号"，则证伪条件命中。结果正负都有价值。
- **不预设结论**：回收轮由实验员按实际观察记录行为，**不得用量表倒推**；工具与协议文本均不暗示"应感到累积"。

### 采集工具 `tools/rq5-instrument.html`

- 自包含、`file://` 可直接开、独立于单轮 `m-instrument.html`（不与 A/B/C/B2 装置混采）。
- 流程：知情同意 → 多轮任务脚本（埋点/回收，含诚实前提声明）→ **客观行为**（B1 锚点主动回忆 / B2 主动回看会话脉络 / B3 完成轮数≥7 / B4 出声思维）→ **RQ5 专项量表 r1–r5**（累积感/非重开/被接上/可追溯/总体，1–7）→ 访谈 I1（有/无进展时指的是"被接上"还是"从头开始"）→ 导出 JSON/CSV。
- 量表只问主观"感到"，不问"系统是否真记住"（后者是账本事实，由 Q-d `digest_kept_seqs` 衡量）——避免诱导被试报告不存在的可解释性。
- `PROTO_VER=rq5-v1`；localStorage key `rq5-records`；CSV 含 BOM + RFC 转义。`window.__rq5` 测试钩子只读/注入，不参与任何判定。
- **验证**：`tools/test_rq5_instrument.js` **17/17**（量表显示、B1/B2 必答校验、字段完整、CSV 对齐、复位、0 JS 错）。

### 顺带修复：m-instrument 连续采集断点

验证 RQ5 工具时发现既有 `tools/m-instrument.html` 的 `btnNext`（下一位被试）存在真 bug：`$('scrDone')` 缺 `#` → `querySelector` 返回 null → reset 抛 TypeError → 屏幕卡在 scrDone，第二位被试无法回到知情同意页。修复为 `$('#'+s)` 并在 `test_m_instrument_m2.js` 补"复位后返回同意页"断言。修复后 m-instrument **31/31**（含新断言）。

> **诚实边界**：本协议与工具是【装置层】交付（✅），**不是 RQ5 结论**。H4.1 仍 [真人] 待验：须真人 ≥7 轮跨 tail=6 边界实测、按 RESEARCH-PLAN §3.5 统计后才可判定。工具汇总只给描述统计、不宣称假设成立。运行时 M1–M4 与 Q-a/Q-d 不得冒充 RQ5 证据。
